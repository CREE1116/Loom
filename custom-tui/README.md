# Loom TUI · 0.1

Codex 코어에 연결하는 독립 Rust TUI다. Ratatui와 기존 `codex-tui`를 사용하지 않고 문자 셀, 화면 갱신, 입력, 포커스, 클릭 영역을 직접 처리한다. 저수준 터미널 입출력에는 Crossterm을 사용한다.

현재 Codex 연결은 과도기 구현이다. 최종 목표는 자체 Orchestrator Core와 자체 Runtime으로 Codex 코어를 완전히 교체하는 것이다. 설계 원칙·단계별 완료 기준은 [프로젝트 구현 기획서](../docs/orchestrator-implementation-plan.md)를 따른다.

## 실행

저장소 루트에서:

```sh
# 화면과 조작을 먼저 체험하기. 모델·도구 실행 없음.
./scripts/custom-tui --demo

# 이 폴더에서 가장 최근에 사용한 대화를 자동 복원한다.
./scripts/custom-tui

# 모델이나 Codex 실행 파일 없이 로컬 코드 증거만 찾는다.
./scripts/custom-tui --explore refresh_session

# 기존 대화를 보존한 채 별도의 새 대화를 시작한다.
./scripts/custom-tui --new

# 지원 모델을 확인하고 이 세션의 모델만 지정하기.
./scripts/custom-tui --list-models
./scripts/custom-tui --model gpt-5.6-sol

# 직접 대화를 지정할 때만 필요하다.
./scripts/custom-tui --resume last

# 특정 작업 폴더 또는 직접 빌드한 Codex 실행 파일 사용.
./scripts/custom-tui --cwd /path/to/project --codex-bin /path/to/codex
```

첫 실행은 Rust 빌드가 필요하다. 기존 Codex 소스를 수정하지 않아도 실행할 수 있다. 최초 검증 대상은 설치된 `codex-cli 0.151.0`이다. 로그인 설정은 기존 Codex가 관리한다.
기본 실행은 최적화된 release 바이너리를 사용한다. 개발 중 빠른 재빌드가 필요하면 `CUSTOM_TUI_PROFILE=debug ./scripts/custom-tui --demo`로 실행한다.

## 화면과 명령

헤더·탭·대화·입력을 구분선으로 분리한다. 입력창은 화면 하단에 고정하고 그 위 영역 전체를 대화 기록에 사용한다. 입력은 한 줄로 시작하고 실제 줄 수만큼 늘어난다. 본문은 터미널 기본색을 유지하며 의미가 있는 표시만 색을 사용한다. 청록색은 에이전트·활동·대기열, 연보라는 사용자 표시, 녹색은 완료·전송, 황색은 승인·우선 실행, 붉은색은 오류·중단·삭제를 뜻한다. 색상과 함께 `◉` 실행·`✓` 완료·`!` 오류 등의 기호를 사용한다. 선택된 탭은 `●`와 회색 배경, 마우스 오버는 더 옅은 배경으로 표시하며 diff 배경색은 기존과 같다.

110열 이상에서는 대화와 작업 상세를 나란히 표시한다. 오른쪽 상세를 열어도 대화와 입력 초안이 유지된다. 좁은 창에서는 선택한 탭을 본문에 표시한다. 폭이 부족하면 일부 탭이 숨겨지며 `/` 메뉴에서 모든 기능에 접근할 수 있다. 선택된 탭은 항상 표시한다. 상시 기록 탭 대신 상단 **세션 ▾** 메뉴(좁은 화면에서는 `/sessions`)에서 현재 대화, 최근 대화, 새 대화를 관리한다. 최근 대화는 제목 줄과 활동 시간 줄을 포함한 전체 행을 클릭하거나 Tab/Enter로 선택해 전환한다. 진행 중인 응답, 승인 요청, 미전송 대기열 등으로 전환이 불가능하면 그 이유를 표시하고 행을 선택했을 때도 안내한다. Diff 상시 탭도 제거했다. **에이전트가 파일 변경을 보고했을 때만** 대화 상단(좁은 화면), 변경 이벤트(대화 타임라인), 활동 패널(넓은 화면)에 `파일 변경 · 내용 보기`가 나타난다. 상세 화면에서는 수정 전후를 비교하고 대화로 돌아올 수 있다. 이 화면은 Codex가 보고한 변경을 보여주며, 작업 폴더 전체의 Git 변경 목록과는 다를 수 있다.

| 명령 | 동작 |
| --- | --- |
| `/help` | 조작 안내 |
| `/questions` | 숨긴 질문 다시 열기 · 선택지와 직접 입력 |
| `/explore QUERY` | Core의 공유 로컬 인덱스에서 코드 증거 검색 (원격 모델 호출 없음) |
| `/skills` 또는 입력 시작의 `$` | 설치된 스킬 선택·검색 |
| `/model` | 다음 메시지의 모델 선택 |
| `/agents` | 에이전트 활동과 별도 터미널 |
| `/diff` 또는 `/diff N` | 보고된 변경 전체 또는 최근 N번째 변경 이벤트 보기(1이 최신) |
| `/chat` · `/panel` | 대화/입력으로 복귀 · 오른쪽 패널 열기/닫기 |
| `/copy [N]` · `/branch [N]` | 최근 N번째 모델 메시지 복사 · 최근 N번째 완료된 모델 메시지에서 분기 |
| `/tool N [next\|prev]` | 최근 N번째 명령 로그 접기/펼치기 · 펼친 출력 페이지 이동 |
| `/agent N [open]` | N번째 에이전트 상세 보기 · 별도 터미널 열기 |
| `/approvals` | 승인 요청 처리 |
| `/approve N M` · `/approve detail N` · `/approve later` | 승인 요청 N의 선택지 M 선택 · 상세 접기/펼치기 · 팝업 닫기 |
| `/permissions` | 현재 샌드박스·승인 정책 확인 및 다음 작업 권한 변경 |
| `/permissions sandbox MODE` · `/permissions approval MODE` | 작업 권한 설정 (위험한 설정은 별도 확인 필요) |
| `/permissions confirm` · `/permissions cancel` | 위험한 권한 변경 확인/취소 |
| `/sessions` 또는 `/resume` | 현재 대화와 최근 대화 열람·전환 |
| `/sessions N` | 표시된 최근 대화 N번으로 바로 전환 (현재 대화 제외, 1부터 시작) |
| `/sessions refresh` · `/sessions more` | 기존 목록을 유지하며 갱신 · 다음 목록 가져오기 |
| `/resume last` 또는 `/resume ID` | 특정 대화 재개 |
| `/new` | 새 대화 시작 |
| `/skill NAME` · `/skill remove NAME` | 스킬 선택 · 선택 해제 (`$` 검색도 가능) |
| `/queue [drop N\|force N\|resume\|clear]` | 대기열 항목 삭제 · 우선 전송 · 재개 · 비우기 |
| `/settings [korean\|english\|panel]` | UI 언어·시작 시 작업 패널 설정 |
| `/quit` | 화면 연결 종료 |

모든 주요 조작은 마우스 없이 `/` 명령 또는 Tab/Shift+Tab과 Enter로 실행할 수 있다. 번호 N은 1부터 시작한다. 복사·분기·파일 변경·도구 로그는 각각 최신 항목을 1로 세며, 승인 요청과 에이전트는 화면에 표시된 순서대로 센다. 상세 화면에서도 일반 문자를 입력하면 입력창으로 돌아온다. 명령 메뉴는 위·아래와 Enter 또는 클릭으로 선택한다. 알 수 없는 `/` 명령은 모델에 보내지 않는다. 스킬은 실제 런타임의 `skills/list`로 읽고, 선택한 스킬의 이름과 경로를 `turn/start`의 `skill` 입력으로 전달한다. 스킬 선택만으로 실행하지 않으며 지시를 입력해 전송한다. 선택한 스킬은 `/skill remove NAME`이나 `×`로 해제한다.

세션 목록은 새로고침 중에도 이전 항목을 보여주며, 새 응답이 성공적으로 도착한 뒤 교체한다. 응답이 잘못되거나 요청이 실패하면 기존 목록을 보존한다. 상단 파일 변경 버튼은 최근 작업에서 보고된 내용만 표시한다. 과거 작업의 변경은 대화 타임라인에 남아 개별적으로 열 수 있다.

설정은 작업 폴더의 `.custom-tui/settings.json`에 저장하며 Codex 설정은 변경하지 않는다. 언어 설정은 UI에 적용하고 사용자 대화와 런타임이 제공한 설명은 원래 언어를 유지한다. 성공 알림은 4초 뒤 사라지고 메시지 전송 시에도 지운다. 오류는 확인할 수 있도록 남긴다.
대기열은 대화 스크롤과 독립적으로 입력창 바로 위에 고정된다. 실행 중 Enter를 누르면 대기열에 추가되므로 별도 추가 버튼 없이 중단 버튼만 남긴다. 최대 3개를 보여주고 나머지 개수를 표시하며, 각 항목의 `×`로 취소하거나 일시정지 헤더를 눌러 재개할 수 있다. 실행 중에는 항목 옆의 **즉시**를 누르면 현재 응답의 중단을 요청하고, 중단 완료를 확인한 뒤 해당 메시지를 먼저 전송한다. 다른 대기 메시지는 순서를 유지한다. 숨겨진 항목도 `/queue force N`(1부터 시작)으로 선택할 수 있다. 중단 요청이 실패하면 대기열을 보존한 채 자동 전송을 멈춘다. 중단은 진행 중인 모델 응답을 멈추며 이미 실행된 도구나 파일 변경을 되돌리지는 않는다.

## 대화 분기

완료된 메시지 오른쪽의 **⑂ 분기 아이콘**을 클릭한다. 마우스를 올리면 하단에 동작 설명을 표시한다. 메시지 내용을 클릭하면 해당 메시지와 아이콘을 강조하고, 키보드로는 Tab으로 아이콘을 선택해 Enter로 실행한다. 분기 버튼은 별도 대화 줄을 차지하지 않는다. 실제 `thread/fork`에 선택한 대화의 `lastTurnId`를 전달하므로 해당 턴의 사용자 메시지와 응답까지 포함한 새 세션이 열린다. 원본은 기록에 남는다. 분기를 연 상태에서 다음 지시를 보내면 새 세션에서 이어진다.

분기는 대화 문맥을 나누는 기능이다. **이미 변경된 작업 폴더의 파일은 되돌리지 않는다.** 실행 중이거나 승인이 남아 있는 동안은 분기를 시작하지 않는다. 데모에서는 예시 분기만 표시한다.

## 질문과 답변

Core의 질문은 대화 초안과 별도인 카드에 표시한다. ↑↓와 Enter로 선택지를 확인하거나 직접 입력하며, Tab/Shift+Tab으로 질문을 이동한다. 모든 질문에 명시적으로 답한 뒤 제출한다. 기본 선택은 자동 제출되지 않는다. Esc/나중에로 숨긴 카드는 `/questions` 또는 질문 알림으로 다시 연다. 민감한 입력은 화면에서 마스킹한다. 전송 실패 시 답변을 유지한다.

`--demo`에서 예시 승인을 처리한 뒤 `질문 데모`를 입력하면 선택지와 직접 입력의 왕복을 확인할 수 있다. [TUI 완성 계획](../docs/tui-completion-plan.md)에 필요한 기능과 순차 구현 기준을 기록했다.

## 조작

일반 문자를 입력하면 버튼 탐색 중이거나 좁은 상세 화면을 보고 있더라도 입력창으로 복귀한다. PageUp/PageDown 및 탐색 중 방향키는 포커스가 위치한 패널을 스크롤한다. 승인 요청의 선택지는 상세 출력보다 먼저 표시되며, 승인 탭에는 대기 건수가 표시된다. 대기열은 현재 응답 완료 후 자동 전송·일시정지·중단 확인 상태를 표시한다. 긴 대화는 완성된 메시지와 전체 대화 행을 캐싱하고, 연속 입력 중에도 화면 갱신을 진행한다.

| 동작 | 키보드 | 마우스 |
| --- | --- | --- |
| 지시 전송 | 입력 중 Enter | 전송 클릭 |
| 줄바꿈 | Alt+Enter 또는 여러 줄 붙여넣기 | 붙여넣기 |
| 조작 대상 탐색 | Tab / Shift+Tab | 대상 클릭 |
| 선택 실행 | Enter | 대상 클릭 |
| 입력으로 복귀 / 상세 닫기 | Esc | 입력창 / 대화 탭 |
| 기록 스크롤 | PageUp / PageDown, 탐색 중 위·아래 | 휠 |
| 최신 위치 | 탐색 중 End | 아래로 스크롤 |
| 텍스트 복사 | 선택한 메시지 Ctrl+Shift+C (또는 입력 초안 복사) | 메시지의 ⧉ 버튼 또는 텍스트 드래그 후 놓기 |
| 텍스트 붙여넣기 | 터미널 기본 붙여넣기 또는 Ctrl+V | — |
| 실행 중단 | Ctrl+C | 중단 |
| 화면 연결 닫기 | Ctrl+Q | 터미널 창 닫기 |

대화·도구·diff·승인·활동을 표시한다. 완료된 명령 로그는 본문보다 흐리게 표시하고 성공·오류·진행 기호의 색은 유지한다. 도구 요약은 펼치거나 접을 수 있다. 긴 도구 출력은 한 번에 24줄씩 표시하며, `이전 24줄`·`다음 24줄`로 넘길 수 있다. 접힌 변경 내역은 최대 12줄만 미리 보여준다. 텍스트를 드래그해 복사하면 기존 메시지 선택 강조가 해제된다. 입력 초안과 각 화면의 스크롤 위치를 유지한다. 새로운 승인 요청이 오면 화면 중앙에 선택 카드가 뜬다. `나중에`나 `Esc`로 닫아도 요청은 유지되며 승인 탭에서 다시 검토할 수 있다.

## 여러 터미널

활동 화면에서 **새 터미널 열기**를 선택하면 macOS Terminal.app에 같은 런타임의 에이전트를 열람하는 화면을 연다. 실행할 인자를 담은 비공개 `.command` 파일을 만들고 macOS의 `open`으로 실행한다. 보조 창은 입력·중단·승인 권한을 갖지 않는다. 창·탭 배치는 Terminal의 설정에 따른다. 현재 창 실행은 macOS Terminal.app을 대상으로 하며, 다른 터미널 앱은 아직 연결하지 않았다.

수동으로 다른 터미널에 연결할 수도 있다:

```sh
./scripts/custom-tui --endpoint ws://127.0.0.1:PORT --agent THREAD_ID
```

같은 작업 폴더의 창은 하나의 분리된 `codex app-server` 프로세스에 연결한다. **터미널은 화면, 대화는 저장된 기록, 에이전트 실행은 별도의 서버가 담당한다.** 터미널을 닫아도 서버가 살아 있는 동안 실행 중인 작업은 계속되고, 저장된 대화는 서버를 재시작해도 다시 열 수 있다. 일반 실행은 이 폴더의 최근 대화를 자동 복원하며, `--new` 또는 세션 메뉴의 **새 대화**로 별도의 대화를 만든다. 저장된 다른 대화는 세션 메뉴에서 선택한다. 새 대화를 열기만 하고 메시지를 보내지 않았다면 최근 대화를 덮어쓰지 않는다. 빈 대화는 Codex가 기록하지 않았을 수 있다. 최근 대화가 더는 존재하지 않으면 자동 복원 대신 새 대화를 연다. 승인을 기다리는 상태에서 처리 창을 닫았을 때의 요청 취소는 Codex 규약을 따른다.

런타임 주소·PID·로그와 최근 세션 ID는 작업 폴더의 `.custom-tui/`에 저장한다. 런타임은 loopback에만 연결한다. 시작 시 Codex 설정과 해당 폴더의 기존 신뢰 기록을 읽는다. 이미 신뢰한 폴더에는 신뢰 질문을 반복하지 않는다. 기록이 없거나 미신뢰인 폴더는 선택 카드에서 **신뢰하고 시작**(Codex 구성 파일에 기록) 또는 **제한 모드로 시작**(해당 세션에만 `workspace-write` 및 `on-request` 적용)을 고른다. 신뢰하기 전에는 세션을 시작하지 않는다. 기존 Codex의 전역 기본값은 임의로 변경하지 않는다. 권한 탭은 실제 코어 정책 및 신뢰 기록을 표시하며 `전체 접근 + 승인 없음` 조합에는 상단 경고를 표시한다. 새 세션에는 검증한 `legacy` 기록 형식을 지정한다. 이 Codex 버전에서 아직 지원하지 않는 paginated 기록 열람은 오류로 표시한다.

## 구현 경계

- `agent.rs`: UI/Core 공통 `AgentEvent`, `AgentCommand`, typed projection과 불투명 승인 토큰.
- `app/events.rs`: provider protocol을 모르는 UI event reducer.
- `backend/codex.rs` · `backend/codec.rs`: Codex 실행·RPC 상관관계·JSON 해석·승인 응답. UI에는 도메인 이벤트만 전달한다.
- `backend/mock.rs`: Codex 형식을 사용하지 않는 `MockCore`. `--demo`의 대화·stream·세션·분기·승인 흐름을 구동한다.
- `core/backend.rs`: 초기 자체 Core 경계. 비동기 LOCAL 탐색을 처리하고 원격 실행은 과도기 Codex backend에 전달한다.
- `core/repository.rs`: 모든 worker가 빌려 쓰는 공유 코드 인덱스·불변 snapshot·탐색 결과 cache.
- `engine.rs`: 문자 셀, Unicode 폭, 변경 영역 출력, 클릭 대상, 터미널 복구.
- `app.rs`: 대화·도구·승인 상태와 키보드/클릭의 공통 동작.
- `transport.rs`: Codex adapter 내부에서 쓰는 WebSocket JSON-RPC 전송.
- `runtime.rs`: 작업 폴더별 런타임 시작·접속과 최근 세션 기록.
- `window.rs`: 터미널 창 실행과 클립보드.
- `preferences.rs`: 작업 폴더별 UI 설정과 언어.
- `main.rs`: 입력과 도메인 이벤트 루프, backend 선택·연결.

작업 중 헤더의 점자 스피너가 120ms 간격으로 움직인다. 모델 출력이 없는 동안에도 진행하며, 완료·승인·blocking 질문 대기·연결 오류에서는 멈춘다. 입력 초안과 읽던 위치는 보존한다.

공유 탐색은 파일 경로·본문·선언 형태를 이용하는 로컬 lexical retrieval이다. 현재 AST 호출 그래프나 vector RAG는 구현하지 않았다. 파일 내용의 SHA-256, 위치, snapshot revision으로 증거를 식별하고, 동일 snapshot·검색어·출력 예산의 동시 요청은 한 번만 검색한다. 반환할 증거의 원문 hash를 확인하여 변경된 결과는 다시 만들고, 실행 중 worker는 기존 불변 snapshot을 유지할 수 있다. 심볼과 관계를 정밀하게 분석하는 기능은 이 자원 위에 확장한다.

UI의 `/explore`는 최대 네 LOCAL 작업을 병렬 실행하며 각각 약 4,096자의 증거 예산을 사용한다. 인덱스는 파일당 512KiB, 메모리에 원문 64MiB를 유지하며 초과분은 snapshot이 소유하는 임시 아카이브로 보관한다. 크기·바이너리 등으로 제외된 파일과 출력 제외·절단 여부를 표시한다. 현재 cache는 Core 인스턴스의 수명 동안 공유한다. 여러 원격 모델의 TaskGraph·patch 격리·장기 memory·무료 모델 routing은 아직 연결하지 않았다.

화면은 첫 버전에서 앱이 소유하는 전체 화면을 사용한다. 과거 대화도 스크롤·클릭할 수 있도록 한 선택이며, 터미널 고유 scrollback을 사용하는 인라인 출력은 후속 작업이다. 모델의 응답은 기본 텍스트로 표시하며 Markdown 구문 강조는 아직 없다.

기본 명령·파일 변경·추가 권한 승인을 지원한다. MCP form/url 요청은 거절·취소만 제공한다. 아직 지원하지 않는 서버 입력 요청은 화면에 알리고 JSON-RPC 오류로 반환한다. 로그인 UI, 파일 참조 선택기와 자동 재접속은 후속 작업이다.

## 검증

```sh
cargo test --manifest-path custom-tui/Cargo.toml
cargo clippy --manifest-path custom-tui/Cargo.toml --all-targets -- -D warnings
./scripts/custom-tui --probe
python3 custom-tui/tests/terminal_smoke.py
python3 custom-tui/tests/config_api_smoke.py
```

`--probe`는 모델 호출 없이 실제 서버 handshake, 두 클라이언트의 동일 세션 메타데이터, 연결 재개를 확인한다. 기본 터미널 검증은 데모를 실제 PTY로 실행하여 키보드·클릭·마우스 오버·선택 탭·명령·스킬·모델·설정·분기·붙여넣기·diff·승인·resize·터미널 복구를 확인한다.

실제 짧은 모델 호출과 두 번째 창의 기록 조회·세션 재개·대화 분기까지 검증하려면:

```sh
python3 custom-tui/tests/terminal_smoke.py --live --model gpt-5.6-sol
```

이 명령은 도구를 사용하지 않는 짧은 응답 하나를 요청한다. 모델 이름은 `--list-models`에 반환되는 값을 사용한다.

OS 창 실행 테스트는 실제 창을 열므로 명시적으로 실행한다:

```sh
cargo test --manifest-path custom-tui/Cargo.toml --test window_launch -- --ignored
```

이 환경에서는 최초 AppleEvents 실행이 시간 초과가 났고 컴퓨터 제어 도구의 Terminal 화면 접근도 차단됐다. 최종 `.command`/`open` 방식은 실행 파일의 인자·권한을 검증했지만 실제 OS 창 생성과 외형은 미확인이다.

공식 연결 규약: [Codex app-server](https://learn.chatgpt.com/docs/app-server).
