# V3 인덱스 수명과 실행 표시 수정

최근 실제 작업 `task-v3-18db8f349cbfb180-68399`는 완료됐지만, 계획 검토에서
`deterministic unit needs calls and objective postconditions`, `tool assertion missing name`,
`workflow requires deterministic actions and receipts` 세 형식 오류를 교정했다.
이를 사용자 대화에 일반 진행 메시지로 그대로 누적한 것이 반복 실패처럼 보였다.
실제 파일 도구 실패와 계획 형식 교정은 다른 사건이다.

## 원인과 변경

- `World::open`은 파일 해시·AST 추출 캐시가 있어도 전체 그래프 JSON을 매 요청마다
  역직렬화했다. `WorkspaceIndex`가 실제 워크스페이스의 그래프를 `Arc`로 유지한다.
  V3 TUI 시작 시 백그라운드에서 준비하고 후속 작업의 Core에 같은 인덱스를 전달한다.
  시작 인덱싱에는 모델 요청이 없다.
- 이후 요청은 파일 메타데이터를 확인한다. 바뀐 파일만 다시 해시·추출하며, 문서만
  바뀌면 코드 그래프 객체를 그대로 쓴다. 소스 변경·추가·삭제 시 그래프를 갱신한다.
  다른 워커의 패치가 반영된 격리 사본의 그래프는 별도로 최신 상태를 확인한다.
  원본 승인 시의 엄격한 revision 검사도 유지한다.
- `goal.contains(symbol.name)`가 문장 속 `m`, `r`을 실제 심볼 언급으로 해석해
  무관한 벤치 코드 16 KB를 전달했다. 식별자 단위 일치로 바꾸고 계획에 읽기·쓰기
  범위가 있으면 그 범위 안에서만 앵커를 선택한다. 요청 의도는 모델의 구조화된
  계획으로 판단하며 한국어 동작 단어를 정규식으로 분류하지 않는다.
- 검토 모델에 계획 모델이 관찰한 루트 목록을 전달한다. 실제로 확인된 경로 이름을
  가정으로 오인하지 않게 하고, 도구 postcondition의 필드별 형식을 명시했다.
- 형식 교정은 기존 이벤트에 구조화된 메타데이터를 붙인다. UI는 본문에 raw 오류를
  반복하지 않고 접힌 기록의 `교정 N`에 모으며, 펼치면 원인을 확인할 수 있다.
  실제 도구 실패 집계는 그대로 유지한다. 과거의 메타데이터 없는 기록은 변조하지 않는다.
- 완료된 도구의 이름과 대상 파일을 진행 본문에 남긴다. 다음 응답을 기다릴 때도
  직전 작업을 지우지 않는다. 원문 id는 본문에서 짧게 표시하고 상세 기록에는 전체를
  보존한다. 워커에 사용자 요청의 언어로 답하고 관찰한 파일 경로를 근거로 들도록 지시했다.

## 검증

회귀 검사는 같은 그래프 객체 공유, 문서 변경 후 객체 유지, 소스 수정·삭제 후 새 심볼,
인덱스 준비 중 모델 호출 없음, 준비 뒤 디스크 그래프가 손상돼도 후속 두 대화가
메모리 객체를 재사용함, 무관한 심볼의 문맥 유입 차단, 교정 기록 보존,
응답 대기 중 직전 파일명 보존을 확인한다.

최종 Core 72개·TUI 236개 테스트가 통과했고 실패는 없다. 화면 검사 495개도 통과했다.
최종 release 바이너리의 실제 PTY에서도 형식 교정 접기, 근거 보존, 셸 실행 상태,
병렬 작업·세션 복원·승인·원본 반영 검사가 모두 통과했다.
수동 측정·데스크톱 실행용 검사 4개는 자동 실행에서 제외했다.

실제 저장소 10,252개 파일·142,709개 심볼을 같은 release 빌드에서 측정했다.
디스크 그래프 재로드는 1,230/1,190/1,198 ms, 인덱스 최초 로드는 1,125 ms,
그 다음 메모리 재사용과 변경 확인은 137/136 ms였다. 변경 없는 소스의 재해시·파싱은
0이며 같은 그래프 객체를 공유했다. 모델 응답 지연을 포함한 전체 속도 개선율은 아니다.

실제 Auto 프로젝트 설명 요청 두 번 모두 파일 수정 없이 완료됐으며 각 5회 모델 요청,
형식 교정 0·도구 실패 0·AST 문맥 0 bytes였다. 첫 답은 한국어 요청에 영어로 나왔다.
언어 지침 추가 뒤 같은 요청은 한국어와 파일 근거를 포함해 완료됐다. 실행 시간은
37.362/23.294초지만 모델 워밍·실행 순서가 달라 성능 비교로 해석하지 않는다.

수치·실제 모델 경로·첫 영어 응답은 [보고서](../bench/results/loom-ux-index-2026-10-05.json)에 남겼다.
release를 빌드했으며 기존 Loom 창은 재시작해야 변경을 사용한다.
