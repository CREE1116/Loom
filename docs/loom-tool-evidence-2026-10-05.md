# V3 도구·AST 실행 근거 표시

V3 대화 투영이 도구 이름을 한국어 작업 분류로 대체하고 검색어를 버렸다.
접힌 작업 기록에는 워커 수와 성공·실패 수만 남아 실제 실행 도구를 알 수 없었다.
AST 인덱스와 코드 문맥, 계획 의존관계의 사용 근거도 UI에 전달되지 않았다.

- 실행 중에는 `search · 검색 실행 중 · alpha`, `read_file · 파일 읽기 실행 중 · alpha.rs`처럼 실제 이름과 대상을 표시한다.
- 완료된 접힌 작업 기록에도 사용한 도구 이름을 남긴다. 펼치면 워커별 대상, 출력, 실패 원인을 확인할 수 있다.
- `AST` 기록에는 인덱스 파일·심볼 수, 해시/그래프 캐시 재사용, 워커에게 준비한 심볼 본문·개요와 위치·바이트 수를 기록한다.
- 계획 그래프·범위 검사가 실제로 추가한 읽기 범위와 의존관계를 기록한다. 모델이 원래 제안한 의존관계와 구분한다.
- 선택 문맥이 없거나 AST를 쓰지 않는 로컬 조회/계획은 그대로 표시한다. 인덱스 존재를 문맥 사용으로 간주하지 않는다.
- 구조화된 이벤트를 Core 로그와 세션에 보존한다. AST JSON은 문자열 중간에서 잘라 복원 불가능하게 만들지 않는다.

AST는 현재 모델이 호출하는 도구가 아니라 Core의 문맥 구성·계획 검사에 사용된다.
기록만으로 모델이 문맥을 활용해 더 좋은 답을 냈다고 판단할 수는 없다.
전체 바이트 수에는 헤더도 포함되며, 심볼별 바이트는 실제 포함된 본문/개요만 센다.
문맥 심볼 상세는 워커당 32개, 계획의 추가 범위·의존관계 상세는 검사당 64개까지 보존한다.
전체 수와 일부 문맥 여부를 별도로 기록한다. 화면의 심볼 수는 워커별 문맥 항목의 합계다.

검증: 변경 전 실패한 도구 이름·검색어 회귀 검사와 실제 PTY 검사를 확인했다.
Core 검사는 실제 모델 요청에 포함된 심볼 본문, 헤더만 잘린 경우의 0 심볼,
빈 문맥, 두 번째 실행의 캐시 재사용, 실제 파일 간 참조에 따른 계획 변경을 확인한다.
UI 검사는 40/80/140열, 실행·실패 상태 색, 도구 이름과 AST 근거의 재시작 복원을 확인한다.
추가 모델 호출은 없다. 성공률·토큰 절감 효과의 AST 활성/비활성 비교 벤치는 별도 검증 대상이다.
