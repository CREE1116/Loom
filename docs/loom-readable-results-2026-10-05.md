# 답변과 실행 상세를 분리한 V2/V3 대화 화면

기존 화면은 답변마다 모델 호출·입출력 토큰·검증 횟수·로그 경로를 붙였고,
실패하면 Core의 오류 문자열을 본문과 알림에 반복했다. 완료된 계획 설명도
답변 앞에 누적해 사용자 대화가 실행 로그처럼 보였다.

## 화면 변경

- 성공한 작업은 모델의 최종 답변을 본문에 그대로 표시한다. 별도의 모델로
  다시 요약하거나 번역하지 않으며, 추가 모델 호출도 없다.
- 승인 대기에서는 수정 내용을 검증했고 승인 후 적용한다는 문장을 덧붙인다.
  중지 요청에는 작업을 중지했다는 문장을 표시한다.
- 실패는 실제 이벤트에서 관찰한 단계(계획 준비·작업 진행·결과 확인)를 설명한다.
  원래 오류는 접힌 **실행 상세**에 보존한다. 오류 문자열이나 요청 동작 단어를
  정규식으로 분류해 원인을 추측하지 않는다. 단계 설명이 원인 진단을 대신하지 않는다.
- 호출 횟수·토큰·검증 횟수·저장 경로·원래 요약·진행 설명은 실행 상세를 펼치면
  확인할 수 있다. 기존 작업 기록, 도구 이름, 파일 대상, AST 근거도 유지한다.
- `README.md · 파일 읽기 완료` 같은 표현은
  `README.md: 내용을 읽었습니다. (read_file)`처럼 문장으로 표시한다.
  확장 도구 이름도 유지한다. 긴 기록 ID는 짧게 표시하되 상세에는 전체를 보존하고,
  작은 화면에서도 읽는 위치 숫자를 확인할 수 있게 줄을 나눈다.
- 모델 없이 도구를 실행한 워커의 완료 문구도 `도구 N회·검증 N개` 대신 작업을
  수행하고 결과를 확인했다는 문장으로 표시한다. 실제 도구 기록·측정치·후조건
  검증은 그대로 보존하며 실행 정책은 바꾸지 않는다.
- 실행 완료와 세션 재시작에 같은 출력 경로를 사용한다. 내부 오류를 알림에
  다시 복제하지 않으며, 준비·적용 중 외부 오류도 펼칠 수 있는 기록으로 남긴다.

실제 터미널 검사에서 승인 후 재검증 중인 셸이 본문에는 보이지만 입력창 상태줄에는
계속 `승인 대기`로 표시되는 기존 문제가 드러났다. 이전 검사는 본문의 동일한
`셸 실행 중` 문자열 때문에 이 문제를 놓쳤다. 응답하지 않은 승인만 대기 상태로
판정하게 바꿨으며, 승인 버튼을 누른 후에는 실제 실행 단계와 Accent 상태를 표시한다.
승인·원본 적용·취소 정책은 변경하지 않는다.

## 검증

- 성공·실패·승인 대기·중지 화면을 40/80/140 너비에서 검사한다.
  통계와 원시 오류가 기본 본문에 없고, 상세를 펼치면 수치·원인이 보존되는지 확인한다.
- 파일 읽기를 문장으로 표시하면서 도구 이름과 대상 파일도 유지하는지 확인한다.
- 승인 후 셸 실행 상태는 한국어·영어와 세 화면 너비에서 별도로 검사한다.
  이 검사에는 본문 도구 문자열을 넣지 않아 상태줄 자체를 검증한다.
- 처음 결과 표시 검사는 25개가 실패했고, 중지 상태의 영어 표기 검사는 3개,
  승인 후 실제 실행 상태 검사는 12개가 실패했다. 수정 후 화면 검사 568개 모두 통과했다.
- TUI 테스트 236개가 통과했고 실패는 없다. 수동 검사 3개는 자동 실행에서 제외했다.
  Core 테스트 77개도 통과했다. 최종 dev/release 빌드와 실제 터미널 검사도 통과했다.
- 실제 터미널은 계획 실패를 의도적으로 재현해 기본 화면의 설명, 상세 클릭 시
  오류·호출 수 보존, 세션 재시작 후 복원을 확인한다. 기존 병렬 워커·원문 읽기·
  AST 표시·셸 상태·승인·원본 적용 검사도 함께 유지한다. 호출 횟수 확인은 새 상세
  표시를 펼쳐 수행하며, 결과나 원본 보존 검사는 약화하지 않는다.

모델이 최종 답변 자체를 어렵게 작성하거나 다른 언어로 답하는 문제를 자동으로
해결한 것은 아니다. 이번 변경은 Core가 자동으로 붙이던 로그와 도구 상태의 표시를
정리한다. 실행 중인 Loom은 Ctrl+Q로 종료하고 다시 시작해야 새 화면을 사용한다.

확인한 성공·실패·복원·승인 경로를 기록했다.
