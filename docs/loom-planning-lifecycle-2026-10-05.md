# V3 조사 계획의 검토 반복과 revision 오류 수정

실제 실패 요청은 `V1 V2 V3코어가 있는데 차이점이 뭐야`이며,
작업 ID는 `task-v3-18db901b0308a0f0-68399`다. 모델 요청 7회,
입력 13,180 / 출력 5,290 토큰을 사용했지만 도구 실행 전에 종료됐다.

## 원인

최초 계획은 읽기 전용 `Inspect`, 단일 `Semantic` 워커였고 형식도 정상이었다.
검토 모델이 워커의 도구 선택 능력을 오해해 이를 결정론적 도구 계획으로 바꿨다.
빈 후조건, `ToolSucceeded.name` 누락을 교정하는 동안 저장소 revision도 바뀌었다.
Core는 저장소 변경까지 응답 형식 오류로 처리해 모델에게 같은 계획을 다시 쓰게 했다.
JSON을 수정해도 이미 바뀐 실행 기준 revision은 복구되지 않으므로 반복이 끝나지 않았다.

## 변경한 실행 규칙

- 단일 읽기 전용 의미 조사에는 별도 계획 검토 모델을 호출하지 않는다.
  정확히 `Inspect`, 워커 1개, 쓰기·의존 단위·후조건 없음, `Semantic`인 계획에만 적용한다.
  실제 도구 권한, 경로, 읽기 전용 계약, 관찰 근거 검사는 그대로 수행한다.
- 수정·절차 실행·다중 워커 조사·결정론적 도구 계획은 독립 검토를 유지한다.
  한국어 동작 단어를 정규식으로 분류하거나 잘못된 JSON을 임의로 고치지 않는다.
- 계획 중 읽기 전용 저장소가 바뀌면 Core가 현재 revision의 인덱스와 그래프를 다시
  확인하고 전체 계획을 검증한다. 성공한 검증만 새 기준 revision을 확정한다.
- 검토가 `Ready`라고 답해도 실행 전에 현재 저장소로 재검증한다. 갱신된 그래프의
  읽기 범위도 실제 실행 계획에 전달한다. 검사 중 다시 변경되면 실행하지 않는다.
- 수정·절차 실행의 기준 revision이 바뀌면 구조화된 `WorkspaceChanged` 오류로
  중단한다. 모델에게 응답 형식을 고치라고 반복 요청하지 않고, 기존 파일은 수정하지 않는다.
- 실제 스키마 오류에는 기존의 제한된 교정 기회를 유지한다. 도구 후조건 이름 누락에는
  필요한 `{ "kind": "ToolSucceeded", "name": "<registered tool name>" }` 형태를 알려준다.

## 검증

새 회귀 검사는 다음을 확인한다.

1. 검토 모델이 없어도 단일 조사는 실제 파일을 읽고 완료한다.
2. 계획 대기 중 파일 변경은 최신 내용으로 조사하며 모델 교정을 만들지 않는다.
3. 수정 계획 중 또는 검토 대기 중 원본 변경은 도구 실행 전에 중단한다.
4. 다중 워커 조사는 검토 모델을 한 번 사용한다.
5. 검토 대기 중 새 함수 참조가 생기면 새 그래프 경계가 실행 계획에도 남는다.

수정 전 첫 세 회귀 검사는 모두 실패했다. 별도의 그래프 갱신 검사는 처음에
검증한 읽기 범위를 버리는 문제로 실패했고, 수정 후 통과했다.
최종 Core 77개·TUI 236개 테스트가 통과했으며 실패는 없다.
화면 검사 507개 및 release PTY의 실제 도구 기록·교정 접기·병렬 작업·세션 복원·승인
검사도 통과했다. 수동 측정·데스크톱 실행 검사 4개는 자동 실행에서 제외한다.

## 실제 요청 재실행

같은 저장소에서 같은 요청을 `--core-intent auto`, `omniroute/auto`로 실행했다.
결과는 `Accepted`, 5회 모델 요청, 입력 10,933 / 출력 2,133 토큰, 41.516초였다.
실제 선택 경로는 `omniroute/antigravity/gemini-pro-agent`였다.
루트·세 코어 목록 조회 4회와 README 읽기 3회 후 비교 답변을 완료했다.
형식 교정 0, 도구 실패 0, 원본 파일 변경 0이다. 단일 조사이므로 계획 검토는 생략됐다.

이는 이번 검토 반복이 해소됐다는 증거다. 실패한 이전 실행과 모델 경로·상태가 같다는
보장이 없으므로 일반적인 속도나 토큰 절감률로 환산하지 않는다.
답변은 영어로 나왔으며 사용자 언어 지시만으로 한국어 출력을 항상 보장하지 못한다.
README 기반 비교의 모든 의미적 주장을 독립적으로 검증한 것도 아니다.
공급자 장애, 반복되는 잘못된 계획, 계속 바뀌는 저장소의 완료를 보장하지 않는다.

실행 중인 이전 Loom 창은 Ctrl+Q로 종료한 후 `scripts/loom-v3`로 재시작해야 한다.
